## 本轮真正改动的边界

不是给旧 JSON 编译器套一层接口。原来的 JToken/JArray 已退出公共模型和编译核心，
运行时不再为了文件 Magic 常量反向依赖编译器。构建、运行时、两类适配器拆为独立程序集。

公共模型使用明确的六种配置类型，构建时允许分配；进入运行时后仍是同一套紧凑列存储。
同一数据从 JSON、CSV、C# 输入，生成完全一致的二进制和访问代码。
新增来源实现 IConfigSource 即可复用校验、编译和生成器，不要求业务层换一套读取 API。

## 关键工程取舍

1. 保留托管数组，不引入 unsafe 和原生对象释放协议。代价是加载仍有复制与分配，优势是旧快照生命周期清晰。
2. 通用的是来源契约，不是任意对象序列化。暂不允许任意嵌套对象、可空值、复杂主键，避免性能语义失控。
3. 默认稀疏哈希索引偏向查询效率；可选二分索引省内存，代价是 O(log n)。两者不改变数据文件。
4. CSV 采取严格的小型方言，不猜测空值、表头和列表语义。原生 XLSX 可另加适配器，本版本仅支持导出 CSV。
5. JSON 依赖仍在完整 UPM 包中供适配器使用，但运行时和构建核心没有此依赖。没有为了“零依赖”破坏旧入口。
6. 保留包名和命名空间减少源码迁移；程序集迁移仍需调整自定义 asmdef 并重编译旧 DLL。
7. 编译和导入不是零分配目标。现有文本导入器及公共模型会物化数据，不是流式大数据管线；64 MiB 产物限制不是构建进程峰值内存上限。

## 自查记录

本次环境没有可用的独立代码审查代理，采用单独一轮自查，不冒称第三方审查。

- 发现并修复 JSON 默认日期转换破坏字符串类型，先复现失败后回归通过。
- 检查 schema 和默认值在空表时也被验证，避免“没有行就绕过结构校验”。
- 检查输入集合被复制，避免调用方修改数组改变待编译文档。
- 检查公共编译产物受加载器接受，旧版本字节/生成器黄金样本保持一致。
- 检查 CSV 引号、多行、表头映射、数值范围、文化环境和错误定位。
- 检查 package 的程序集依赖、固定 GUID 和独立消费路径，不仅在合并源码的 .NET 工程里测试。
- 检查热路径实现没有把来源抽象或 ConfigValue 引入每帧读取。

仍需实际目标项目完成手机峰值内存和长时间业务压测，以及多人独立代码评审。
本交付为可用的独立框架版本，不把这些未完成项包装成“通用九分已认证”。
